# Scopebook

[English](README.md) · [Исследование рынка](docs/MARKET_RESEARCH.ru.md) · [План запуска](docs/LAUNCH.ru.md)

Личное рабочее пространство для независимых дизайнеров и разработчиков. Оцените проект, проверьте, покрывает ли его стоимость затраты вашего времени, определите объём работ и подготовьте предложение для клиента. Дополнительные запросы можно оценить отдельной сметой.

Интерфейс, шаблоны предложений, документы для клиента и скачиваемые примеры доступны на русском и английском языках. Автоматически выбирается первый поддерживаемый язык из настроек браузера; переключатель **RU / EN** запоминает ручной выбор. Смена языка сохраняет существующие предложения и несохранённый пользовательский текст. Числа и даты отображаются в выбранном формате; валюта и суммы автоматически не конвертируются.

**Бизнес-модель:** одно сохранённое предложение бесплатно; Pro за **29 долларов одним платежом** — до 500 сохранённых предложений, экспорт без отметки сервиса и резервные копии. Это ценовой эксперимент перед запуском. Продажи и спрос пока не подтверждены. [Исследование рынка](docs/MARKET_RESEARCH.ru.md) объясняет выбор идеи и ограничения выводов; [план запуска](docs/LAUNCH.ru.md) описывает путь к первым платящим пользователям.

## Запуск на компьютере

Нужны **Node.js 24**, npm и Git. Бесплатная версия работает без ключей API и внешних сервисов.

Если репозитория ещё нет на компьютере:

```bash
git clone https://github.com/Dank0m/GPTrepo.git
cd GPTrepo
```

Если папка уже существует, перейдите в неё. Затем установите зависимости и запустите разработку:

```bash
npm ci
npm run dev
```

Откройте в браузере адрес `http://localhost:5173`. Редактор находится по пути `/app`, готовый пример — `/app?sample=1`. Терминал должен оставаться запущенным. Vite работает на порту 5173 и перенаправляет запросы `/api` на сервер Express, порт 3001.

Адрес приложения для локальной разработки по умолчанию — `http://localhost:5173`. Используйте один и тот же адрес, чтобы проверки источника запросов и cookie работали корректно. При выборе другого адреса задайте совпадающее значение `APP_URL`.

Для запуска собранного приложения:

```bash
npm run build
APP_URL=http://localhost:3001 NODE_ENV=production npm start
```

Команды с присваиванием переменных перед `npm start` приведены для Bash. На хостинге переменные можно задать через его настройки.

Собранный сервер обслуживает главную страницу, рабочее пространство, файлы и API на порту 3001. Переменная `PORT` меняет порт. При публикации `APP_URL` должен точно совпадать с публичным HTTPS-адресом сайта, включая нестандартный порт, если он есть, но без пути, параметров и фрагмента. Для локальной разработки поддерживается HTTP. Сервер слушает адрес `0.0.0.0`.

## Что работает

- Адаптивная главная страница, интерактивный калькулятор и пример предложения.
- Сметы по отдельным задачам в USD, EUR или GBP, с предоплатой и налогом с продаж.
- Внутренняя целевая ставка за час, запас времени, фактическая ставка и расчётная маржа. Эти внутренние показатели не попадают в документ для клиента.
- Включённые работы, исключения, количество раундов правок, срок действия предложения, сроки проекта и настройки студии по умолчанию.
- Предпросмотр для клиента, печать или сохранение PDF через браузер, скачивание отдельного HTML-документа и сметы на дополнительные работы. Скачиваемый образец содержит демонстрационные данные, а не настоящий клиентский проект.
- Сохранение в браузере по явной команде, проверка импортируемого JSON, резервные копии в Pro, копирование, удаление, поиск и обработка ошибок хранилища.
- Необязательная оплата через Stripe, доступ к Pro после проверки платежа, ключи восстановления и отзыв лицензии при полном возврате или открытии платёжного спора.

Стоимость проектов в приложении — оценка, а не подтверждённая выручка. Маржа сравнивает цену проекта с бюджетом вашего времени по целевой ставке с учётом запаса. Накладные расходы, платёжные комиссии и налог на доход в неё не включены. Налог с продаж не считается прибылью. Экспортируемые предложения не являются подписанными договорами, счетами или юридической консультацией. Электронная подпись, приём оплаты от ваших клиентов, облачная синхронизация и автоматические рассылки в эту версию не входят.

## Данные и лицензии

Предложения и настройки студии хранятся локально в браузере. Содержание предложений не отправляется в API. Очистка данных сайта удаляет их. Печатайте или экспортируйте важные предложения и храните приватные резервные копии. Резервные копии Pro в JSON содержат клиентскую информацию: сохраняйте их в безопасном месте. Перед импортом проверяется весь файл. Предложения с совпадающими идентификаторами заменяются только после подтверждения; остальные сохранённые предложения остаются. Для надёжной работы хранилища резервная копия ограничена 500 предложениями и 5 МБ.

Pro использует секретный ключ восстановления в cookie с атрибутами `HttpOnly` и `SameSite`; при HTTPS также задаётся `Secure`. Сервер хранит в SQLite только хеш ключа, идентификаторы платежей и платёжных сессий, а также записи о полученных уведомлениях Stripe. Перед очисткой cookie сохраните ключ восстановления в настройках. Он возвращает доступ к лицензии в другом браузере, но **не восстанавливает предложения**. Любой, у кого есть ключ, может использовать лицензию. Ограничение платных функций на стороне клиента — практический выбор для этой версии, а не защита от целенаправленного обхода.

## Подключение платежей перед продажами

Без настроенных ключей покупка отключена. Нажатие на кнопку тарифа не имитирует списание денег и не выдаёт Pro. Владелец должен подключить собственный торговый аккаунт. Сначала выполните [условия запуска](docs/LAUNCH.ru.md): настройте поддержку, правила возврата и конфиденциальности, проверьте возможность работы с платёжным провайдером.

1. Задайте переменные из `.env.example` в защищённых настройках хостинга либо в локальном файле `.env`, который не отслеживается Git. Не добавляйте настоящие ключи в репозиторий. В `APP_URL` укажите реальный HTTPS-адрес сайта.
2. Задайте **обе** переменные: `STRIPE_SECRET_KEY` и `STRIPE_WEBHOOK_SECRET`. Начните с тестового режима Stripe. `STRIPE_PRICE_ID` необязателен; если он указан, цена должна быть активной, разовой и составлять 29,00 USD. Иначе сервер сам создаёт позицию оплаты с фиксированной стоимостью 29 долларов. Переданная браузером цена игнорируется.
3. Зарегистрируйте обработчик `POST /api/billing/webhook` для событий `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.expired`, `charge.refunded` и `charge.dispute.created`. Подпись проверяется по исходному, неизменённому телу запроса. Серверу нужен исходящий доступ к `api.stripe.com`.
4. До включения реальных платежей проведите на опубликованном сайте настоящую покупку **в тестовом режиме**, отмену оплаты, возврат и восстановление лицензии. Автоматические тесты используют имитацию платёжного API и настоящую генерацию подписей Stripe; это не заменяет проверку интеграции с провайдером. Соблюдение платёжных и налоговых требований своей юрисдикции остаётся задачей владельца.

Лицензия выдаётся только после проверки оплаченной сессии на 29 USD и успешно завершённого платежа `PaymentIntent`, для которого нет полного возврата или открытого спора. Выдача привязана к браузеру, начавшему оплату. Изменения по уведомлению Stripe выполняются в транзакции, а повторная доставка того же события не повторяет операцию. Полный возврат и открытие спора отзывают ключ восстановления; частичный возврат сохраняет лицензию. Потеря ответа при возврате с оплаты и одновременные запросы безопасно приводят к повторной выдаче того же ключа. Восстановление работает после перезапуска сервера только при сохранении базы данных.

Ключ Stripe API, подставляемый сетевым прокси, может использоваться для HTTPS-запросов к `api.stripe.com`. Однако секрет подписи уведомлений должен быть доступен процессу как **настоящее секретное значение**, поскольку подпись проверяется локально. Значения-заглушки исходящего прокси недостаточно. Задайте секрет через защищённые настройки среды выполнения хостинга, не через чат или отслеживаемые файлы.

## Публикация

Для рабочей версии нужны Node.js 24 и производственные зависимости npm. TypeScript-код сервера компилируется во время `npm run build`.

```bash
npm ci
npm run build
npm prune --omit=dev
APP_URL=https://your-real-domain.example NODE_ENV=production npm start
```

Адрес с `.example` — образец: замените его своим зарегистрированным доменом. Настройте HTTPS, разместите **`.data` на постоянном диске с правом записи** и делайте резервные копии SQLite. При необходимости задайте путь к постоянному хранилищу через `DATABASE_PATH`. Начальная схема развёртывания предполагает один постоянно работающий процесс Node. Временная файловая система бессерверного хостинга теряет записи о покупках и не подходит для реальных продаж без постоянного хранилища. Ограничения частоты запросов действуют внутри процесса и рассчитаны на один экземпляр приложения. Не запускайте независимые реплики с несогласованными копиями базы.

`Dockerfile` описывает многоэтапную сборку на Node 24, запуск без прав администратора и каталог данных `/app/.data`. Передавайте `APP_URL` и секреты при запуске контейнера. Рецепт контейнера предоставлен, но в этой среде сам контейнер не собирался; собранный сервер проверялся отдельно. Запрос `GET /api/health` возвращает `{ "ok": true, "service": "scopebook" }`. Запрос `GET /api/billing/status` показывает, настроена ли оплата и активна ли текущая лицензия, не раскрывая секретов.

## Проверки

```bash
npm run build        # Проверка TypeScript, сборка интерфейса и компиляция сервера
npm test             # Расчёты, импорт/экспорт, проверка оплаты и восстановление
npm run test:e2e     # Пользовательские сценарии в Chromium на компьютере и телефоне
npm run samples      # Пересоздание примеров HTML и PDF на двух языках; нужен Chromium
```

Браузерные тесты используют системный Chromium по пути `/usr/bin/chromium`, если он есть. Иначе установите браузер Playwright командой `npx playwright install chromium`. Переменная `CHROMIUM_PATH` позволяет выбрать другой исполняемый файл. Средство запуска тестов автоматически поднимает собранный сервер: сначала выполните сборку. Проверяются русский и английский интерфейсы, выбор и сохранение языка, сохранность текста, документы, резервные копии и ошибки хранилища. Тесты браузерного интерфейса Pro имитируют только ответ о правах доступа, чтобы проверить экспорт и резервное копирование; серверные тесты отдельно проверяют выдачу доступа после оплаты. Во время разработки реальные платежи, публикация сайта, рассылки и покупки не выполнялись.

## Структура репозитория

- `src/App.tsx`: рабочее пространство, редактор, интерфейс экспорта и работа с лицензией.
- `src/lib/proposals.ts`: структура предложения, расчёты, безопасные печатные документы и резервные копии.
- `server/`: API Express, интеграция Stripe и хранилище покупок SQLite.
- `docs/`: исследование рынка с источниками и экспериментальный план запуска.
- `tests/`: браузерные проверки на компьютере и мобильном экране.

Облачные задачи уже выполняются в изолированных средах. Используйте существующую копию репозитория; создавать дополнительный Git worktree для обычной разработки не требуется.
